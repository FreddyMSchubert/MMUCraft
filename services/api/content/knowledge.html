Basic Server Advice

The server has several custom systems layered on top of vanilla Minecraft. Most of them are designed to feel like vanilla-adjacent discoveries rather than obvious plugin commands.

The most important habit is simple: read item names, hover over items, and test things carefully. Some items only work while held, some only work while equipped, and some only respond to specific interactions like right-clicking blocks or entities.

### charm_basics 0 "the basics of charms"

Charm Basics

Charms are custom server-side items. They usually look like normal Minecraft items, but they have extra behaviour handled by the server mod.

A charm can be passive, active, held, equipped, or consumable. For example, one charm may work every tick while worn in the correct equipment slot, while another may only activate when you right-click with it in your hand.

  • Held charms usually activate from your main hand or off hand.
  • Equippable charms usually care about an armour slot.
  • Consumable charms behave like food, potions, or charged-use items.
  • Broken charms may still exist as items, but their level is too low to provide an effect.

The server tracks charm data directly on the item stack. That means two visually similar items can behave differently if their stored charm data is different.

### ### crafting_staff_notes 0 "how the crafting staff works"

The Crafting Staff

The Crafting Staff is a convenience item for opening crafting functionality without needing to place a crafting table. This is especially useful while travelling, mining, or building in awkward spaces.

It is not meant to replace infrastructure entirely. Treat it as a portable tool rather than a full base management system.

Tip: if an item opens a screen, avoid spam-clicking it. Wait for the server to respond before using it again.
### ### ender_storage_staff 1 "portable ender chest access"

Soulbound Storage Staff

Some staff items can open personal storage. The Soulbound Storage Staff opens your ender chest inventory from wherever you are.

This does not create a shared society storage. It is still your own ender chest. Anything you place inside follows normal ender chest behaviour.

Because the item opens a real inventory menu, be careful when using it near danger. Mobs, lava, or other players will not politely wait for you to finish organising your items.

### ### priority_system_hint 1 "how knowledge unlock priority works"

Knowledge Unlock Priority

Knowledge does not unlock in pure random order across the whole wiki. Each locked section has a priority number. Lower numbers unlock first.

For example, all priority 0 entries are unlocked before priority 1 entries. Within the same priority group, the next unlock is random.

This lets early discoveries teach basic mechanics before later discoveries reveal deeper, stranger, or more powerful interactions.

### ### equipment_slot_warning 2 "why some charms only work in specific slots"

Equipment Slot Rules

Some charms are picky about where they are equipped. A boots charm may do nothing in your helmet slot, even if the item technically exists in your inventory.

This matters because the server checks both the stored charm data and the slot currently holding the item. If the charm definition says it belongs in a specific slot, the effect can be ignored elsewhere.

  • Boot-like charms usually care about feet.
  • Armour-like charms usually care about the matching armour slot.
  • Held tools usually care about the hand used to activate them.
### ### fake_item_identity 2 "how fake items are identified"

Fake Item Identity

Fake items reuse vanilla item IDs. The client sees a normal item, but custom model data and server-side components allow the server to treat that item as something special.

This is why two items with the same vanilla base can look or behave differently. The visible item type is only part of the story.

The server uses stable fake item IDs internally. These IDs are important because they let the mod recognise custom items even when the display name, lore, or resource pack art changes later.

### ### resource_pack_note 2 "why the server resource pack matters"

Server Resource Pack

The server resource pack controls how many custom items appear on your client. Without it, many fake items may look like ordinary vanilla items.

The behaviour is server-side, so the item can still work without the correct art, but the intended experience depends on the resource pack being enabled.

If custom items suddenly look wrong, check whether your client rejected or disabled the server resource pack.

### ### mining_travel_tips 3 "safe mining and travel habits"

Mining and Travel Tips

Custom tools and charms can make travel easier, but they can also make players overconfident. Keep normal survival habits: carry food, blocks, a water bucket, spare tools, and an escape plan.

If you discover a charm that changes movement, test it somewhere safe before using it near the void, lava, cliffs, or other players' builds.

  1. Test movement charms in an open field.
  2. Check whether fall damage is affected.
  3. Check whether the effect works while sneaking.
  4. Check whether it behaves differently in water.
### ### economy_common_sense 3 "basic economy common sense"

Economy Common Sense

If the server develops shops, trades, or society events, remember that custom items may change the value of normal resources.

An item that saves time can be economically powerful even if it does not directly create blocks or ores. Convenience has value.

Be careful with trades involving rare charms. If you do not understand what a charm does yet, do not trade it away casually.

### ### staff_debugging_note 4 "how to report custom item bugs"

Reporting Custom Item Bugs

Good bug reports are specific. Instead of saying “the charm broke,” include what item you used, where you used it, what you clicked, what you expected, and what actually happened.

Useful details include:

  • Your Minecraft username.
  • The approximate time the bug happened.
  • The item name and, if visible, any lore text.
  • Whether you were holding, wearing, consuming, or placing the item.
  • Whether the issue happened once or repeatedly.

This helps staff check server logs and reproduce the issue.
